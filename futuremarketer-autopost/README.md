# 퓨처마케터 당근 자동 등록 (학습용 프로토타입)

엑셀에 적어 둔 상품을 골라 **당근 비즈프로필의 가격표와 소식에 한 번에 올리는** 1인 사장님용 도구입니다.

- 상품 글(대본)이 없으면 **Claude** 가 쓰고, 사진이 없으면 **GPT** 가 그림을 만들어 내 PC 에 저장한 뒤 그 그림으로 올립니다.
- 브라우저 조작은 **Aside 브라우저** 창에서 눈으로 볼 수 있습니다. 학습용이라 자동화가 화면을 어떻게 누르는지 일부러 보여 줍니다.
- 한 일은 화면에 한 줄씩 남고, 대시보드의 **작업 기록**에서 성공·실패와 그 순간의 브라우저 화면을 다시 볼 수 있습니다.

## 한눈에 보기

| 메뉴 | 하는 일 |
|---|---|
| 대시보드 | 연결 상태, 상품 현황 숫자, **작업 기록**(시도마다 한 줄, 성공·실패 모두, 멈춘 순간의 화면)을 봅니다. 「비즈니스 계정 열기」(관리 화면)와 「당근에서 업체 보기」(손님이 보는 업체 프로필), 성공한 줄의 「등록된 소식 보기」(소식 공유 주소)는 로그인된 Aside 창으로 열립니다. 등록 기능은 없습니다. |
| 상품 등록 | 엑셀 불러오기 → 목록에서 고르기 → 한 번에 등록 → 진행 과정(단계, 화면 캡처, 기록) 보기 |
| 계정 설정 | 당근 계정 연결·해제, 비즈프로필 고르기(여러 개일 때), AI 연결(API 키 또는 구독 로그인), 지침(프롬프트) 고치기 |

상품 하나를 등록하면 이렇게 진행합니다.

```
글(대본 그대로 / 없으면 Claude) → 이미지(내 사진 / 없으면 GPT 가 만들어 저장)
  → 가격표(대표 사진·상품명·가격) → 소식(사진 모두 올린 뒤 제목·본문 → 다음 → 완료)
```

구성은 단순합니다. 화면(Streamlit)과 자동화 엔진(워커)은 내 PC 에서 돌고, 기록은 Docker 로 띄운 MySQL 에 남고,
워커가 Aside 브라우저를 열어 당근 비즈니스 화면을 조작합니다. 실제 당근에 올리기 전에 쓸 수 있는 **연습용 화면**도 들어 있습니다.

## 1. 로컬 컴퓨터 세팅 (사람이 직접 할 때)

### 준비물

| 항목 | 설명 |
|---|---|
| 운영체제 | 프로젝트의 설치와 자동 등록은 macOS에서 확인했습니다. Windows에서 Aside 브라우저는 설치할 수 있습니다. 프로젝트 워커는 macOS에서 실행합니다. |
| Python 3.12 | 설치 후 `python3.12 --version`으로 확인합니다. [Python 공식 다운로드](https://www.python.org/downloads/) |
| Docker Desktop | 설치 후 앱을 열어 둡니다. 프로젝트의 MySQL 8.4를 실행합니다. [Docker Desktop 설치 안내](https://docs.docker.com/desktop/) |

| AI 연결 (둘 중 하나) | **API 키**(Anthropic, OpenAI) 또는 이 컴퓨터에 로그인된 **Claude Code·Codex 구독**. 둘 다 없어도 연습용(`FM_AI_MODE=mock`)으로는 끝까지 돌려 볼 수 있습니다. |
| 당근 비즈니스 계정 | 실제로 올릴 때만. 연습용 화면에는 필요 없습니다. |

### Aside 브라우저 설치

- **macOS**에서 공식 다운로드 페이지를 열고 Mac에 맞는 Apple Silicon 또는 Intel 설치 파일을 받습니다. `Aside.dmg`를 열고 Aside 아이콘을 **응용 프로그램(Applications)** 폴더로 끌어 놓습니다. 응용 프로그램에서 Aside를 한 번 실행해 초기 설정을 마칩니다. [Aside 공식 다운로드](https://aside.com/download)
- **Windows**에서는 같은 다운로드 페이지에서 시스템 종류에 맞는 Windows 설치 파일(x64 또는 ARM64)을 받고 실행합니다. 설치가 끝나면 시작 메뉴에서 Aside를 열고 초기 설정을 마칩니다. [Aside 공식 다운로드](https://aside.com/download)
- macOS 프로젝트가 찾는 기본 실행 파일은 `/Applications/Aside.app/Contents/MacOS/Aside`입니다. 다른 폴더에 설치했다면 프로젝트의 `.env`에서 `FM_ASIDE_PATH`에 Aside **실행 파일**의 전체 경로를 적습니다.

Windows의 Aside 설치와 이 프로젝트의 실행 조건은 별개입니다. 프로젝트 워커는 Unix 파일 잠금(`fcntl`)을 사용하고 Aside 프로필 종료에 `pgrep`을 사용하므로 Windows PowerShell에서 바로 실행할 수 없습니다. 아래 프로젝트 실행 명령은 macOS에서 사용합니다.

### macOS 프로젝트 세팅 순서

프로젝트 폴더(`futuremarketer-autopost`)에서:

```bash
cp .env.example .env                       # 1. 설정 파일. 기본값 그대로 써도 됩니다
docker compose up -d                       # 2. MySQL 8.4 (127.0.0.1:3317)
python3.12 -m venv .venv                   # 3. 가상환경
source .venv/bin/activate
pip install -r requirements.txt            # 4. 패키지
export PYTHONDONTWRITEBYTECODE=1           #    캐시 파일(.pyc)을 만들지 않습니다(내 PC 경로가 폴더에 남지 않게)
python scripts/check_setup.py              # 5. 점검: 필수 항목이 모두 [통과] 인지
python -m streamlit run streamlit_app.py   # 6. 실행
```

브라우저에서 http://127.0.0.1:8501 을 엽니다. DB 표는 처음 뜰 때 자동으로 만들어지고, 자동화 엔진(워커)도 화면과 함께 뜹니다. 화면을 끄면 워커도 꺼집니다.

> Playwright 는 Aside 에 붙어서 조작하므로 `playwright install` 로 브라우저를 따로 받을 필요가 없습니다.

### 처음 켠 뒤 할 일

1. **연습용으로 먼저 돌려 보기(권장)**: `.env` 에 `FM_DAANGN_TARGET=practice`, `FM_AI_MODE=mock` 을 적고 다시 켭니다.
   계정 설정 → "당근 계정 연결" → 연습용 로그인 버튼 → 상품 등록 → "불러오기" → 상품 체크 → 등록. 자세한 내용은 아래 [연습용 화면으로 먼저 해 보기](#연습용-화면으로-먼저-해-보기).
2. **실제로 쓰기**: `.env` 를 `FM_DAANGN_TARGET=real`, `FM_AI_MODE=live` 로 돌리고 다시 켠 뒤, 계정 설정에서 당근 계정과 AI 를 연결합니다. 아래 [쓰는 순서](#쓰는-순서앱을-켠-뒤)를 따릅니다.

### 잘 안 될 때

| 증상 | 해결 |
|---|---|
| "데이터베이스에 연결하지 못했습니다" | Docker Desktop 이 켜져 있는지 확인하고 `docker compose up -d`. 처음 뜰 때는 10~20초 걸립니다. |
| "표 구조가 지금 코드와 다릅니다" | 아주 오래된 DB 입니다. `python -m futuremarketer.db_init --reset` (등록 기록이 지워집니다) |
| 3317 포트를 이미 쓰고 있음 | `docker-compose.yml` 의 `127.0.0.1:3317` 과 `.env` 의 두 DB 주소에서 포트를 같이 바꿉니다. |
| "Aside 브라우저를 찾지 못했습니다" | [Aside 브라우저 설치](#aside-브라우저-설치)를 따라 응용 프로그램에 설치합니다. 다른 폴더에 설치했다면 `.env`의 `FM_ASIDE_PATH`에 실행 파일 경로를 적습니다. |
| 구독 로그인 "연결 확인" 실패 | 터미널에서 `claude`, `codex` 를 한 번 실행해 로그인을 마치고, 최신 버전으로 올립니다. |
| 자동화 엔진이 꺼져 있음 | 왼쪽 아래 "자동화 엔진 켜기". 기록은 앱 데이터 폴더의 `data/logs/worker.log` |

## 2. AI 바이브 코딩으로 세팅하기

Claude Code, Codex, Cursor 같은 AI 코딩 도구에게 이 폴더를 열어 주고 아래 문장을 그대로 붙여 넣으면, 도구가 이 README 를 읽고 세팅을 끝까지 진행합니다.

```text
이 폴더의 README.md 를 끝까지 읽고 「AI 에이전트용 세팅 지시서」를 순서대로 따라
내 컴퓨터에 당근 비즈니스 자동 등록 시스템을 세팅해 줘.
설치나 로그인처럼 내가 해야 하는 일이 나오면 멈추고 무엇을 하면 되는지 알려 줘.
마지막에 점검 결과와 접속 주소를 알려 줘.
```

### AI 에이전트용 세팅 지시서

> 이 절은 AI 코딩 도구가 그대로 따라 하도록 쓴 것입니다. 작업 폴더는 이 README 가 있는 폴더입니다.
> 프로젝트 실행 절차는 macOS 기준입니다. Aside가 없으면 위 [Aside 브라우저 설치](#aside-브라우저-설치)를 안내합니다.

**지켜야 할 것**

- 사용자의 실제 당근 계정에 **아무것도 올리지 않는다**. 가격 등록·소식 등록은 사용자가 화면에서 직접 누른다. 세팅 확인은 연습용 화면(`FM_DAANGN_TARGET=practice`)으로만 한다.
- 확인용으로 브라우저를 띄울 때는 창 없이(`FM_BROWSER_HEADLESS=1`) 띄운다. 사용자의 화면에 창을 띄우지 않는다.
- API 키·비밀번호를 `.env`, 코드, 로그, 대화에 적지 않는다. API 키는 사용자가 앱의 계정 설정 화면에서 직접 넣는다.
- 당근 로그인, Claude Code·Codex 로그인, Docker Desktop·Aside 설치처럼 사람이 해야 하는 일은 대신 하지 않는다. 무엇을 하면 되는지 짧게 알려 주고 기다린다.
- 기존 DB 를 지우는 명령(`db_init --reset`, `docker compose down -v`)은 사용자가 허락할 때만 쓴다.
- `.env` 의 `FM_DAANGN_TARGET` 을 사용자 허락 없이 바꾸지 않는다. 실제 ↔ 연습용을 바꿔 앱을 켜면 **이미 연결된 당근 로그인이 해제되고 지워진다.** 자동 시험(7·8번)은 시험 전용 DB 와 임시 폴더를 쓰므로 사용자의 연결에 영향이 없다.
- 프로젝트 파일은 고치지 않는다. 세팅에 필요한 것은 `.env` 와 `.venv` 뿐이다.

**순서** — 각 단계의 「확인」이 맞아야 다음 단계로 간다.

| # | 할 일 | 확인 |
|---|---|---|
| 1 | 운영체제·도구 확인: `uname -s`, `python3.12 --version`, `docker --version`, `ls /Applications/Aside.app` | macOS(`Darwin`)인지. 없는 도구는 사용자에게 설치를 부탁하고 멈춘다(Python 은 `uv python install 3.12` 또는 `brew install python@3.12` 를 제안할 수 있다). |
| 2 | Docker 가 켜져 있는지: `docker info` | 실패하면 "Docker Desktop 을 켜 주세요"라고 하고 기다린다. |
| 3 | `.env` 가 없으면 `cp .env.example .env` | 이미 있으면 덮어쓰지 않는다. |
| 4 | `docker compose up -d` 후 `docker compose ps` | `fm-autopost-mysql` 이 `healthy` 가 될 때까지 기다린다(최대 1분). 3317 포트 충돌이면 사용자에게 알린다. |
| 5 | `python3.12 -m venv .venv` → `.venv/bin/pip install -r requirements.txt` | 오류 없이 끝나는지 |
| 6 | `PYTHONDONTWRITEBYTECODE=1 .venv/bin/python scripts/check_setup.py` | 필수 항목이 모두 `[통과]` 이고 종료 코드 0. `[확인 필요]` 줄의 안내대로 고치고 다시 돌린다. |
| 7 | `PYTHONDONTWRITEBYTECODE=1 .venv/bin/python -m pytest -q` | DB·화면·등록 흐름 테스트가 통과합니다. Aside를 사용하는 시험은 8번에서 실행합니다. |
| 8 | (Aside 가 있으면) `PYTHONDONTWRITEBYTECODE=1 FM_BROWSER_TESTS=1 .venv/bin/python -m pytest -q tests/test_browser_practice.py` | 통과. Aside 를 창 없이 띄워 연습용 화면에 실제로 가격·소식을 올려 본다. |
| 9 | 앱 실행: `PYTHONDONTWRITEBYTECODE=1 .venv/bin/python -m streamlit run streamlit_app.py` (백그라운드로) | `curl -s http://127.0.0.1:8501/_stcore/health` 가 `ok` |
| 10 | 사용자에게 알린다 | 아래 「끝나면 사용자에게 알려 줄 것」 |

**끝나면 사용자에게 알려 줄 것**

1. 접속 주소: http://127.0.0.1:8501
2. 점검 결과(6~8번)를 한 줄씩.
3. 사용자가 직접 할 일:
   - 계정 설정 → **당근 계정 연결**: Aside 창이 뜨면 당근 비즈니스에 로그인합니다(로그인 정보는 이 컴퓨터의 전용 브라우저 프로필에만 남습니다).
   - 계정 설정 → **AI 연결**: Claude(글)·GPT(이미지) 각각 "API 키" 또는 "구독 로그인"을 고르고 "연결 확인". 대본과 사진이 모두 있는 상품만 올린다면 AI 연결 없이도 됩니다.
   - 상품 등록 → **불러오기** → 상품 체크 → 등록. 처음에는 한두 개로 해 보세요.
4. 연습용으로 먼저 보고 싶다면 `.env` 에 `FM_DAANGN_TARGET=practice`, `FM_AI_MODE=mock` 을 적고 앱을 다시 켜면 된다는 것(이미 실제 당근에 연결해 두었다면 그 연결은 해제된다는 것도 함께).

## 3. 참고 자료

### 쓰는 순서(앱을 켠 뒤)

1. **계정 설정 → 당근 계정 연결**: Aside 창에 당근 비즈니스 로그인 화면이 뜹니다. 로그인을 마치면 창이 저절로 닫히고 "연결됨"으로 바뀝니다. 이후 등록은 그 로그인으로 진행합니다.
   - **비즈프로필이 여러 개일 때**: 연결된 뒤 「다른 비즈프로필 고르기」를 누르면 Aside 창에 비즈프로필 목록이 뜹니다. 하나를 고르면 이후 등록·삭제는 그곳으로 갑니다. 한 번 골라 본 비즈프로필은 「등록할 비즈프로필」 목록에 남아, 브라우저 없이 「이 프로필로 바꾸기」로 오갈 수 있습니다. 「등록 완료」 기록은 비즈프로필마다 따로라, 바꾼 곳에서는 같은 상품을 다시 등록할 수 있습니다. 진행 중이거나 확인을 기다리는 작업이 있으면 바꾸지 않습니다.
2. **계정 설정 → AI 연결**에서 Claude(글), GPT(이미지)마다 ‘API 키’ 또는 ‘구독 로그인’을 고르고 저장합니다. API 키 방식에서 ‘연결 확인’을 누르면 지정한 모델을 조회합니다. 사용할 모델은 `FM_CLAUDE_API_MODEL`, `FM_OPENAI_IMAGE_MODEL`로 지정합니다.
3. **상품 등록 → 불러오기**: 연결된 엑셀(`samples/상품목록.xlsx`)을 읽습니다. 다른 파일을 올려 불러올 수도 있습니다. 상품마다 지금 등록할 수 있는지 검사해 "등록 가능 / 등록 불가(이유)"로 보여 줍니다.
4. **상품을 체크하고 "선택한 n개 등록"**: 오른쪽 "등록 진행"에 단계와 브라우저 화면, 기록이 실시간으로 나옵니다.
   - **가격표 등록**은 기본으로 켜져 있습니다. 끄면 선택한 상품의 가격표 등록을 건너뛰고 소식만 올립니다. 엑셀 가격은 필수 입력값으로 사용합니다.
   - 상품 목록이나 초안의 사진을 누르면 원본 비율로 크게 볼 수 있습니다.
   - 글과 사진만 준비하려면 **게시하지 않고 초안만 준비**를 체크하고 **선택한 n개 초안 준비**를 누릅니다. 상품 줄의 **가격 없는 소식 초안**에서 결과를 볼 수 있습니다.
   - 소식 작성 화면에 제재 안내가 뜨거나 선택한 업체의 작성 화면을 확인할 수 없으면 **게시 보류**로 멈춥니다. 처음부터 제한된 계정은 가격표 저장 전까지만 진행합니다.
5. **연결 해제**: 계정 설정에서 누르면 이 컴퓨터에 저장된 당근 로그인 정보(전용 브라우저 프로필)와 계정 화면이 찍힌 캡처를 지웁니다.

기본 엑셀에는 상품 6개가 있습니다.

| 상품 | 소식 대본과 사진 |
|---|---|
| P001 안경 | 정면·옆면에서 볼 수 있는 프레임 디테일을 소개합니다. 사진 2장입니다. |
| P002 무선 헤드폰 | 소음 제어와 EQ 사용법을 설명합니다. 사진 3장입니다. |
| P003 수달 장난감 | 로프·노즈워크·삑삑이로 하는 놀이를 소개합니다. 사진 3장, 가격표 금액은 25,000원입니다. |
| P004 아쿠아마린 목걸이 | 펜던트의 물고기자리 모양과 체인을 설명합니다. 사진 4장, 가격표 금액은 250,000원입니다. |
| P005 커피 드리퍼 · P006 접이식 캠핑 테이블 | 상품정보와 가격만 있어 Claude가 소식 글을 쓰고 GPT가 이미지를 만듭니다. |

P001~P004에는 2차로 받은 상품정보를 반영했습니다. 엑셀을 이미 불러온 설치에서는 **상품 등록 → 불러오기**를 누르면 새 대본과 가격이 반영됩니다.

### 엑셀 형식

첫 시트, 첫 행이 머리글입니다.

| 칸 | 필수 | 설명 |
|---|---|---|
| 상품코드 | ○ | 영문·숫자·`-`·`_`, 40자까지. 같은 코드는 같은 상품으로 봅니다. |
| 상품명 | ○ | 당근 가격표의 항목 이름이 됩니다. 항목 칸은 15자까지라 넘으면 띄어쓰기에서 줄이고, 전체 이름은 추가 설명(50자)에 적습니다. |
| 가격 | ○ | 원 단위 숫자. `24900`, `24,900원` 모두 됩니다. |
| 상품정보 |  | AI 가 글·그림을 만들 때 근거로 삼는 사실 |
| 소식제목 |  | 비우면 상품명(대본이 있을 때) 또는 AI 가 쓴 제목. 당근 소식 제목 칸은 30자까지라 넘으면 띄어쓰기에서 줄입니다. |
| 대본 |  | 적으면 **한 글자도 바꾸지 않고** 소식 본문으로 올립니다. 비우면 Claude 가 씁니다. |
| 이미지 |  | 이미지 폴더(`samples/images`) 안의 파일 이름을 쉼표로 구분. 비우면 GPT 가 그림을 만듭니다. |

가격표와 소식에 올릴 사진이 7MB 이상이면 업로드용 JPEG를 만들어 7MB 미만으로 줄입니다. 앱에 저장된 원본 사진은 그대로 보관합니다. 기본 샘플 사진 12장은 모두 2.3MB 이하입니다.

### 등록 한 건이 진행되는 순서

| 단계 | 내용 |
|---|---|
| 글 | 대본이 있으면 그대로 사용합니다. 비어 있으면 Claude가 상품정보와 사진(최대 3장)을 보고 사용법이나 특징을 씁니다. 엑셀 가격은 가격표에 입력합니다. |
| 이미지 | 사진이 있으면 그대로. 없으면 **이때** GPT 가 그림을 만들어 앱 데이터 폴더의 `generated/` 에 저장하고 그 그림으로 등록합니다. |
| 가격 | Aside 에서 가격표 화면을 열어 "가격 추가 → **대표 사진(첫 번째 사진)** · 항목 · 정가 입력 → 완료 → 저장". 같은 이름의 항목이 있으면 새로 만들지 않고 그 항목을 "수정"합니다. |
| 소식 | 소식 작성 화면을 열어 "**사진 모두 올리기**(사진 버튼 → 내 앨범에서 선택, 10장까지) → 제목·본문 입력 → 다음 → 완료". 다음 단계의 소식 태그·단골 알림·채팅 설정은 기본값 그대로 둡니다. |

사업자등록증이 없어도 소식 작성이 가능한 계정에서는 가격표와 정보성 소식 등록을 진행합니다. 사업자 인증을 확인할 수 없는 상태에서 대본에 금액이나 판매·주문 안내가 감지되면 소식 단계에서 멈춥니다. 이때 앞서 저장한 가격 항목은 앱에서 삭제할 수 있습니다. 당근은 소식으로 상품을 판매하거나 유료 서비스를 제공할 때 사업자 인증을 요구합니다. [당근 비즈프로필 운영정책](https://cs.kr.karrotmarket.com/wv/faqs/32201?from_kind=biz_profile_policy&type=business)

**등록과 재시도**

- 접수는 버튼을 눌렀을 때만 일어납니다. 화면이 다시 그려지는 것으로는 작업이 생기지 않고, 같은 클릭이 두 번 들어와도 한 번만 접수합니다.
- 상품당 진행 중인 작업은 하나입니다(DB 의 생성열 UNIQUE).
- 끝난 단계는 다시 하지 않습니다. 실패한 상품을 다시 등록하면 멈춘 단계부터 이어서 합니다.
- "저장"·"완료"를 누른 뒤 결과를 확인하지 못하면 **다시 누르지 않습니다.** "확인 필요"로 두고, 사람이 당근에서 확인한 뒤 "올라가 있음 / 올라가지 않음"을 고릅니다.
- 이미 올린 상품은 엑셀을 고쳐 다시 불러와도 "등록 완료"로 남습니다. "등록한 뒤 내용이 바뀜"으로 알려 주고, 다시 올릴지는 그 상품의 버튼으로 사람이 고릅니다(모르고 두 번 올리지 않게).
- **당근에서 삭제**: 등록된 상품 줄의 「당근에서 삭제」를 누르고 확인 문구에서 「지우기」를 한 번 더 누르면, Aside 로 당근 가격표의 항목과 소식을 지웁니다(소식 → 가격 순서). 지운 것은 되돌릴 수 없습니다. 끝나면 상품은 다시 「등록 가능」이 되고, 대시보드 작업 기록에 「삭제 완료」가 남습니다. 일부만 올라간 상품(가격만 올라가고 소식은 실패한 경우)은 올라간 것만 지웁니다. 이미 없으면 그대로 끝나므로, 멈췄을 때 다시 눌러도 안전합니다.
- "등록 완료"는 (상품, 연결된 곳)마다 따로 기억합니다. 연습용 화면에 올렸던 상품은 실제 당근에 연결하면 "등록 가능"으로 보이고, 실제에 올린 기록은 연습용을 다녀와도 그대로 남습니다. 다른 비즈프로필도 같습니다.
- 접수한 뒤 연결된 계정이 바뀌면 그 작업은 진행하지 않습니다(다른 계정에 올리지 않게).
- AI 가 쓴 글에 입력에 없던 금액이 있으면 올리지 않습니다.
- AI 가 만든 그림에는 오른쪽 아래에 작게 "AI 생성 이미지"라고 표시합니다.
- 화면에서 요소를 찾지 못하면 짐작해서 누르지 않고 멈춥니다. 멈춘 순간의 화면은 대시보드 작업 기록에 붙고, 화면 구조(HTML)는 앱 데이터 폴더의 `diagnostics/` 에 남습니다.
- 실패한 상품을 다시 등록해도 앞선 실패 기록은 지워지지 않습니다. 작업 기록에는 시도마다 한 줄씩 쌓입니다.

### 연습용 화면으로 먼저 해 보기

실제 당근에 올리기 전에, 내 PC 안에서만 뜨는 연습용 화면으로 전체 흐름을 볼 수 있습니다. 주소 모양과 버튼 글자를 실제 화면과 같게 맞춰 두어 같은 자동화 코드가 그대로 돕니다.

```bash
# .env
FM_DAANGN_TARGET=practice      # 연습용 화면(http://127.0.0.1:18765)에 등록
FM_AI_MODE=mock                # (선택) AI 연결 없이 예시 글·그림으로
FM_BROWSER_HEADLESS=1          # (선택) 창 없이. 개발·시험할 때
```

등록 대상을 바꾸면(실제 ↔ 연습용) 이전 대상의 연결은 해제되고 그 로그인 정보도 지워집니다. 다시 돌아오면 로그인을 새로 합니다.
연습용 로그인은 버튼 하나만 누르면 됩니다. 등록한 가격과 소식은 연습용 화면의 "홈"에서 볼 수 있고, 앱 데이터 폴더의 `practice` 를 지우면 초기화됩니다.

### 무엇이 어디에 저장되나

| 내용 | 위치 |
|---|---|
| 상품, 작업, 진행 기록, 연결 방식 | MySQL (Docker 볼륨) |
| **당근 로그인 정보**(전용 브라우저 프로필), **API 키** | `~/Library/Application Support/futuremarketer-autopost/` |
| 엑셀 사본, 사진 사본, **AI 가 만든 이미지**(`generated/`), 화면 캡처, 로그 | 위 폴더 아래 `data/` |

로그인 정보·API 키·화면 캡처는 모두 **프로젝트 폴더 밖**에 둡니다. API 키는 DB·로그·`.env` 에 넣지 않고 계정 설정 화면에서만 넣습니다. 화면은 127.0.0.1 에서만 열립니다.
위치를 바꾸려면 `.env` 의 `FM_PRIVATE_DIR`, `FM_DATA_DIR` 을 씁니다. AI 가 만든 이미지를 보려면:

```bash
open ~/Library/Application\ Support/futuremarketer-autopost/data/generated
```

### 다른 사람에게 보낼 때

폴더를 그대로 압축하지 마세요. `.venv` 와 캐시 파일(`__pycache__`)에는 내 PC 의 경로가, `.env` 에는 내 설정이 들어 있습니다.

```bash
python scripts/make_share_zip.py      # 코드·샘플·문서만 담은 zip 을 프로젝트 폴더 옆에 만듭니다
```

Git 으로 공유한다면 `.gitignore` 가 같은 것들을 제외합니다.

### 알아둘 점

- 당근 비즈프로필 소식은 하루 5개까지 올릴 수 있습니다. 대시보드에 오늘 올린 수가 보입니다.
- 내 계정에 사람이 하듯 올리는 방식이지만, 자동 프로그램 사용은 서비스 운영정책의 제한을 받을 수 있습니다. 실제 계정에 쓰기 전에 정책을 확인하고, 적은 수로 천천히 올리세요.
- 직접 작성한 소식 대본은 문구를 그대로 사용합니다. 새 엑셀을 올리기 전에 안내 문구와 상품 정보를 확인하세요.
- 현재 DB 구조는 `schema:6`입니다. `schema:3`·`schema:4`·`schema:5`는 앱을 켤 때 기록을 지우지 않고 순서대로 올립니다. 지원하지 않는 구조라 "표 구조가 지금 코드와 다릅니다"가 나오면 먼저 기존 데이터를 백업하고 초기화 필요 여부를 확인하세요. `python -m futuremarketer.db_init --reset`은 등록 기록을 지우므로 초기화하기로 결정한 경우에만 실행합니다.
